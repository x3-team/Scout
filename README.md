# Scout

CPU-first лабораторный цифровой прототип робота-инспектора. Это отдельный проект:
SkillForge не используется и не изменяется.

## Быстрый запуск на Windows

Нужен Python 3.12 или новее. Откройте PowerShell в каталоге проекта:

```powershell
py -3 -m scout --scenario normal --seed 1 --output runs/normal.json --html runs/normal.html
Start-Process .\runs\normal.html
```

Если py отсутствует, используйте python вместо py -3.
Зависимости устанавливать не нужно: используется стандартная библиотека.
GPU, ROS 2, облако, API-ключи и оборудование для демонстрации не нужны.
После получения исходников демонстратор полностью работает офлайн.

HTML показывает полигон, препятствия, круговой габарит двухколёсного робота,
траекторию и результаты. Кнопка воспроизведения и ползунок показывают завершённый
расчёт, а не управляют движущимся роботом.

## Воспроизводимые сценарии

| Сценарий | Итог | Проверка |
| --- | --- | --- |
| normal | COMPLETED, A → B → C → HOME | Три нормальные точки и возврат |
| deviations | COMPLETED, две изменённые точки | Подготовленные extra_box в B и missing_item в C |
| blocked | BLOCKED / PATH_BLOCKED | Коробка перекрывает сегмент перед A; остановка до контакта |
| sensor-failure | FAULT / SENSOR_UNAVAILABLE | Дальномер отключается на второй модельной секунде |

```powershell
py -3 -m scout --scenario deviations --seed 1 --output runs/deviations.json --html runs/deviations.html
py -3 -m scout --scenario blocked --seed 1 --output runs/blocked.json --html runs/blocked.html
py -3 -m scout --scenario sensor-failure --seed 1 --output runs/sensor-failure.json
```

Код завершения 0 означает полный обход. Код 2 означает остановку маршрута,
ошибку датчика или тайм-аут: JSON при этом создаётся. Код 1 означает ошибку
ввода или записи. Ошибки синтаксиса аргументов также возвращают 2, но без отчёта.
Для blocked и sensor-failure ненулевой $LASTEXITCODE в PowerShell ожидаем.

Одинаковые сценарий, seed и версия дают побайтово одинаковый JSON на одной
платформе и версии Python. Хеш сценария включён в отчёт. Между разными платформами
могут быть небольшие отличия тригонометрии; смысловые результаты проверяются CI.
Seed влияет только на шум дальномера. Он не создаёт отклонения в нормальных точках.
Симуляция рассчитывается быстрее реального времени; времена в отчёте модельные.

Свой сценарий можно скопировать из scout/scenarios/normal.json и передать его
полный путь через --scenario. До старта проверяются конечность и границы координат,
свободное место для полного габарита и ограничения вычислительной работы.
SCOUT-01 требует ровно три точки с уникальными ID. Их порядок задаёт маршрут.

## Модель и ограничения

Дифференциальный привод содержит два колеса с радиусом 0,04 м и расстоянием
между колёсами 0,18 м. Габарит робота — окружность радиусом 0,14 м.
Полигон 3 × 2,4 м содержит неподвижные прямоугольные препятствия.

Робот поворачивается на месте и движется вперёд до 0,15 м/с. Дальномер с ограниченной
дальностью и шумом возвращает консервативный запас хода до касания полного габарита.
При запасе ≤ 0,22 м робот прекращает движение. Автоматического объезда нет.
Дополнительная проверка перемещения между отсчётами предотвращает пропуск тонких
препятствий и завершает миссию ошибкой при попытке пересечения.

**Отклонения берутся непосредственно из JSON-сценария. Настоящая камера и
компьютерное зрение не используются.** Это отмечено в каждом результате,
в метаданных JSON и в HTML. Точность зрения на этих данных не вычисляется.

Положение идеализировано, торможение мгновенное. Симулятор не моделирует людей,
скольжение, инерцию и реальные задержки. Его результаты не подтверждают
физическую безопасность оборудования.

## Отчёт

JSON содержит статус и причину завершения, посещённые и запланированные точки,
инспекции с источником доказательств, конечную позу, журнал, траекторию,
полную конфигурацию и метрики: время, длину пути, число посещений и изменений,
долю посещённых точек, минимальный измеренный запас хода и срабатывания защиты.

completion_ratio = 1 означает посещение всех трёх точек. Для полного успеха
дополнительно нужны status = COMPLETED и returned_home = true.
simulated_contacts = 0 отражает модель, где пересечения отклоняет защита;
обязательно учитывайте collision_guard_activations.

Каждый выходной файл записывается атомарной заменой. runs/ исключён из Git.
Данные не отправляются в сеть.

## Тесты

```powershell
py -3 -m unittest discover -s tests -v
py -3 scripts/check_demos.py
```

30 тестов проверяют полный и частичный обход, отклонения, блокировку до контакта,
отказ и устаревание датчика, тайм-аут, остановку при исключении, кинематику,
тонкие препятствия, некорректную геометрию, воспроизводимость JSON, маркировку
доказательств, встраивание данных в HTML и коды завершения CLI.
В один тест входит серия из 20 seed: это испытания симуляции, не физического робота.

GitHub Actions запускает проверки на Windows и Linux с Python 3.12 и 3.13,
генерирует четыре JSON/HTML-отчёта, проверяет синтаксис JavaScript и сохраняет
артефакты. runs/*.js создаются для проверки синтаксиса; конечные HTML автономны.
Для локальной проверки синтаксиса JavaScript дополнительно нужен Node.js;
сам Python-демонстратор от него не зависит.

## Архитектура и развитие

См. [архитектуру](docs/architecture.md) и [контракт отчёта](docs/report-format.md).
RobotPort и InspectionPort отделяют миссию от симулятора и подготовленных данных.
Физическое оборудование потребует отдельных адаптеров, реального времени,
калибровки, независимой остановки моторов и испытаний.
Текущий исполнитель намеренно отклоняет доказательства камеры, чтобы глобальная
маркировка synthetic оставалась правдивой.

Изменения SCOUT-01 проверяются через PR; автоматическое слияние не используется.
