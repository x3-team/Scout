# SCOUT-02 Инспекция изображений на CPU

Модуль обрабатывает пиксели двух файлов: эталона и нового снимка. Он ищет
изменения внутри плоской области с четырьмя ArUco-маркерами. Маршрут робота
и синтетическая инспекция SCOUT-01 остаются отдельным режимом.

## Запуск на Windows

Python 3.12 или 3.13, PowerShell в папке Scout. Изолируйте зависимости:

```powershell
py -3 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements-vision.txt
.\.venv\Scripts\python.exe -m scout.vision board --output-dir runs/vision/board
```

Печатайте board.svg на A4 в альбомной ориентации, в масштабе 100%, без
автоматического обрезания. Размер листа изображения 297 × 207,9 мм.
Маркеры: DICT_4X4_50, ID 10, 20, 30 и 40. Сохраняйте их расположение,
ориентацию и белые поля. В PNG и SVG один и тот же рисунок.

Поместите лист на плоский стол или щит. Для первой проверки используйте
плоские предметы: карточки, наклейки, контуры упаковки. Область инспекции
расположена в центре между маркерами. Четыре маркера должны целиком попадать
в оба снимка; заполните листом большую часть кадра. Сделайте эталон и новый
снимок с умеренным изменением положения камеры. Сохраните оригиналы отдельно
от папки результата:

```powershell
.\.venv\Scripts\python.exe -m scout.vision inspect --reference datasets/photos/reference.jpg --current datasets/photos/current.jpg --input-kind photograph --output-dir runs/vision/my-inspection
Start-Process .\runs\vision\my-inspection\report.html
```

Результат: inspection.json, выровненные изображения, карта различий,
выделенные области и автономный report.html. Число changed_fraction — доля
значимо изменившейся площади, не вероятность и не распознавание класса предмета.
Цветовые изменения также учитываются. Оригинальные метаданные EXIF в PNG/HTML
не переносятся. Исходные фотографии не публикуются и не отправляются в сеть.

Коды CLI: 0 — получено CHANGED или UNCHANGED; 2 — INCONCLUSIVE с отчётом;
1 — ошибка файла, параметров, зависимостей или записи. Входные изображения
должны быть вне папки результата. Папка результата содержит только создаваемые
программой файлы; повторный запуск обновляет их и удаляет устаревшие маски.

## Как принимается решение

1. Декодирование изображения, ограничение размера и уменьшение длинной стороны
   до 2400 пикселей для ограниченной нагрузки на CPU.
2. Поиск четырёх заданных маркеров; повтор ID, слишком маленький или сильно
   наклонённый маркер запрещает уверенное сравнение.
3. Независимое выравнивание обоих изображений к плоскости 1000 × 700 пикселей.
   Гомография оценивается по 16 углам с RANSAC; контролируются согласованность,
   ошибка проекции и заполнение области инспекции.
4. Проверка резкости по маркерам и пересвета/недосвета области инспекции.
5. Компенсация умеренного глобального изменения освещения по неподвижной полосе
   вокруг области, затем сравнение в пространстве Lab.
6. Фильтрация мелкого шума, выделение связных областей и доли изменений.

Результаты: CHANGED, UNCHANGED, INCONCLUSIVE. Повреждённая регистрация,
отсутствие маркеров, размытие, некорректная экспозиция, слишком сильная смена
освещения или изменение большей части области дают INCONCLUSIVE.

Гомография описывает одну плоскость. Она не устраняет параллакс объёмных коробок.
Для объёмных сцен требуется повторяемое положение камеры и отдельная проверка;
в этой версии качество на таких сценах не заявляется. Небольшая окклюзия внутри
области может выглядеть как изменение предмета: алгоритм не определяет её причину.
Калибровка для метрической 3D-позы в этом модуле не выполняется.

## Происхождение изображений

--input-kind обязателен: photograph или synthetic. В обоих случаях OpenCV
действительно обрабатывает пиксели. Это отличается от SCOUT-01, где отклонение
читается из JSON без обработки изображений. Происхождение указывается оператором;
программа не подтверждает подлинность снимка, поэтому authenticity_verified=false.

Для программных тестов предусмотрены процедурные изображения:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s vision_tests -v
.\.venv\Scripts\python.exe scripts/check_vision_demos.py
```

Девять отчётов в runs/vision/reports показывают добавление, удаление, изменение
ракурса и освещения, отсутствие маркера, перекрытие, размытие и тёмный кадр.
Все они помечены как синтетические. Эти результаты не измеряют качество на
настоящих фотографиях.

## Оценка настоящих фотографий

Используйте формат datasets/photo-manifest.example.json. Метки CHANGED/UNCHANGED
задаются вручную и не передаются алгоритму. split=tuning нужен для подбора
параметров, split=evaluation — для отдельной оценки. Одна scene_id не может быть
в обоих разделах. Совпадающие байты файлов между разделами и дубли новых кадров
в оценке отклоняются. Программная проверка не заменяет ручной проверки разметки.

```powershell
.\.venv\Scripts\python.exe -m scout.vision evaluate --manifest datasets/photos/manifest.json --output runs/vision/evaluation.json
```

Для лабораторной приёмки нужны минимум 20 изменённых и 20 неизменённых новых
кадров в evaluation с declared input_kind=photograph. Цели: recall ≥ 0,90,
false_positive_rate ≤ 0,10, coverage ≥ 0,90. INCONCLUSIVE на изменённом кадре
считается пропуском; любой INCONCLUSIVE снижает coverage и общую точность.
Параметры фиксируются до оценки, а не подгоняются по её результатам.

Набор настоящих фотографий пока не предоставлен; реальная лабораторная точность
остаётся неизмеренной. Первые программные пороги — исходные значения для стенда.
Папки datasets/photos и datasets/private исключены из Git.
